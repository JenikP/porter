Build a complete, polished, frontend-only Porter MVP prototype with:
1. Customer frontend
2. Driver frontend

4. Shared connected demo state so actions in one role can affect the others without a real backend

- no real backend

- no real payment provider
- no real maps provider

Use local code, shared mock data, localStorage/IndexedDB where appropriate, and a shared frontend state layer so the prototype behaves like one connected marketplace.

CONNECTED PROTOTYPE REQUIREMENT
-------------------------------
The three frontends must behave like parts of one marketplace.

Because there is no backend yet, create a shared frontend mock platform layer that acts as the single source of truth for prototype data.

Preferred approach:
- create a shared package/module such as:
  packages/mock-platform/
- centralize:
  - users
  - customer profiles
  - drivers
  - vehicles
  - jobs
  - quotes
  - job events
  - payments
  - disputes
  - notifications
  - rate cards
  - driver documents
- persist state locally
- provide shared functions/actions
- use a role-aware demo shell or same-origin setup so Customer, Driver and Admin views can see the same prototype data
- if separate app folders remain, connect them through a common shared mock-state mechanism and a demo launcher that makes role switching easy
- do not duplicate separate disconnected hard-coded datasets for each role

Examples of connected behavior:
- Customer creates a job -> Driver can see the offer
- Driver accepts -> Customer sees Driver Assigned
- Driver changes status -> Customer sees job status change
- Admin can reassign -> Driver/Customer state updates
- Admin changes rate card -> new quotes use the new values
- Customer raises dispute -> Admin sees it
- Admin resolves dispute -> Customer sees resolution
- Driver document expires -> Driver cannot go online
- Driver completes delivery -> Customer sees proof and completed status
